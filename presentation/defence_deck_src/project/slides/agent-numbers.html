Step ② in detail · how each agent produces its numbers

8 + 6 + 13 = 27 numbers, and where each comes from

Object finder → 8

A detector (YOLOv11m) trained on this archive’s object classes. It draws boxes, each with a class and a confidence. For each of the 8 classes we keep its best box confidence (0 if no box).

Example: person 0.972 (the boy; the woman 0.90) · animal 0.013 (the hen) · child 0

Scene matcher → 6

SigLIP, zero-shot: trained on millions of web images with captions. It scores how well the picture matches a sentence (0–1): 5 scene sentences, plus the best of 7 “not a scene” sentences.

Example: family 0.327 · drawing 0.157 · teaching 0.046 · others 0

Describer → 13

LLaVA-OneVision, zero-shot, a model that answers questions about images. Asked 13 separate yes/no questions (5 scene + 8 object classes); we read how likely its first word is “yes”: P(yes) ÷ (P(yes) + P(no)).

Example: child 0.995 · person 0.989 · drawing 0.985 · family 0.485 · teaching 0.427 · animal 0.311 · rest ≤ 0.11

The scene matcher and the describer are used without training on the scene classes: the class names are simply written into their sentences and questions. What is learned is the next step — how much each of the 27 numbers counts. (Training them was tested too: no clear gain for the system, Section 7.7.)

Part 3 of 5 · The corrected design

How does each agent know how to produce numbers for all the classes? The object finder is a detector trained on boxes of this archive’s object classes: it draws boxes, each with a class and a confidence, and for each of the eight classes we keep its best box confidence, or zero if it drew none. That gives 8 numbers. For the example: person 0.972, which is its box on the boy, while the woman gets 0.90; it calls neither of them a child, and gives the hen only 0.013. The scene matcher, SigLIP, was trained by its makers on millions of web images with captions, so it can score how well any picture matches any sentence. We give it five scene sentences, one per class, and seven “not a scene” sentences, and keep the five scene scores plus the best “not a scene” score: 6 numbers. For the example, family fits best at 0.327, then drawing at 0.157. The describer, LLaVA, answers questions about images; we ask 13 separate yes/no questions, one per scene class and one per object class, and read how likely its first word is “yes”. That gives 13 numbers. For the example: child 0.995, person 0.989, drawing 0.985, family 0.485, teaching 0.427, and animal 0.311 for the hen. The key point: the scene matcher and describer are used without training on our classes — the class names are written into the sentences and questions. I also tested training them on the archive: the scene matcher alone improves, but the system does not clearly improve, because its mappings already learn from the same labels. What we learn is the next step: how much each number counts.
