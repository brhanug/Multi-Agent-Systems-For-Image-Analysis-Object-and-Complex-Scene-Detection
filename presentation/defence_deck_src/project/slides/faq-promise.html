Why conformal risk control, not a hand-picked threshold

A hand-picked threshold

Says nothing about how many wrong answers get through.

Conformal risk control

Turns a target (e.g. 5% approved and wrong) into the threshold, with a guarantee that needs only calibration pictures like the new ones.

The published alternative

Selective classification bounds the error among approved pictures — stricter, so at the same 5% it approves 16% instead of 63%.

The guarantee is an average over calibration sets. Learn then Test makes it hold per set with high probability (sets over the level: 41.5% → 17.5%).

Backup B

Why a risk promise instead of a threshold I choose? A hand-picked threshold says nothing about how many wrong answers slip through. Conformal risk control turns the target into the threshold, using calibration pictures, and gives a guarantee that only needs those pictures to be like the new ones. I compared it with the published alternative, selective classification with guaranteed risk: that method bounds the error among the approved pictures, which is stricter, so at the same stated five percent it approves only 16 percent instead of 63. At a matched approval rate they land on the same point. And because conformal risk control holds on average, I also tested Learn then Test, which makes the promise hold for a given calibration set with high probability.
